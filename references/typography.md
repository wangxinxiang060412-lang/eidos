# Typography System & Multilingual Legibility

排版承载界面 80% 以上的信息传递。排版的首要职责是**清晰层级与舒适可读性**，绝不允许为了追求所谓的“极简高级感”而把字号缩到看不清或把字色淡到发灰。

---

## 1. 统一字阶体系（按场景弹性取舍，不机械一刀切）

一个产品内保持 **1 套清晰的语义字阶**，严禁每个页面临时发明新字号（例如一页用 13px、隔壁用 13.5px、另一页用 15px）：

| 语义角色 | 桌面 / Web 常规 | 移动端 (iOS/Android/小程序) | 字重 (Weight) | 行高 (Line-Height) | 字距 (Tracking) | 适用场景 |
|---|---|---|---|---|---|---|
| `display` | `32–40px` | `26–32px` | `600–700` | `1.10–1.20` | `-0.025em` | 仅限营销首屏、关键超大指标、游戏大标题 |
| `title-lg` | `22–24px` | `20–22px` | `600` | `1.25–1.30` | `-0.015em` | 页面主标题 |
| `title-md` | `18px` | `17–18px` | `600` | `1.30–1.35` | `-0.01em` | 区块标题、弹窗/抽屉标题 |
| `title-sm` | `15–16px` | `15–16px` | `600` | `1.35–1.40` | `0` | 卡片/列表主标题 |
| `body` | `14–15px` | `15–16px` | `400` | `1.50`（中文 `1.60`） | `0` | 正文、列表说明、输入框文本（**Web 移动端输入框 ≥16px 防 iOS 自动缩放**） |
| `body-sm` | `13px` | `13–14px` | `400–500` | `1.45–1.50` | `0` | 次要正文、表单标签、按钮文字 |
| `caption` | `12px` | `11–12px` | `400–500` | `1.35–1.40` | `+0.01em` | 时间戳、脚注、徽标、辅助提示（**严禁常规可读文本小于 11px**） |
| `mono-data` | 继承上下文 | 继承上下文 | `500–600` | `1.20–1.40` | `0` | 金额、ID、代码、坐标、倒计时（强制 `tabular-nums`） |

## 2. 字体栈与中英文混排规范

1. **最多 2 套字体家族**：1 套主 UI 字体（系统原生优先以保证性能与原生熟悉感，或品牌选定无衬线/衬线）+ 1 套等宽字体（**严格仅用于代码、ID、表格对齐数据，严禁把技术产品的普通 UI 标签全写成等宽字**）。
2. **现代跨端高质量系统字体栈（Web 参考）**：
   ```css
   --font-sans: -apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC",
                "Hiragino Sans GB", "Microsoft YaHei", "Segoe UI", Roboto,
                "Noto Sans SC", sans-serif;
   --font-mono: ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas, monospace;
   ```
   *(若引入自定义 Web 字体，如 Inter / Geist / Noto Sans SC，必须配置 `font-display: swap` 与尺寸匹配回退，防止 FOIT 白屏与 CLS 布局跳动。)*
3. **中英文与数字混排细则**：
   - **中文正文行高比纯英文高 0.1–0.15**（纯英文 `1.45–1.5`，中文及中英混排 `1.6–1.7`），因为汉字方块满格无上下伸部，行高太紧会糊成黑墙。
   - 避免对中文使用过大负字距（负 tracking 会导致汉字粘连，中文标题字距维持 `0` 至 `-0.01em`）。
   - 中文产品无需强行把所有按钮和标题转 `UPPERCASE`；英文 UI 默认采用 **Sentence case（句首大写）**，读速高于全大写。

## 3. 数字排版与光学细节

1. **等宽数字铁律（`tabular-nums`）**：所有价格、余额、计数器、倒计时、进度百分比、表格数字列必须开启 `font-variant-numeric: tabular-nums`（SwiftUI `.monospacedDigit()` / Compose `fontFeatureSettings = "tnum"`），防止数字跳动时整行文字左右抖动。
2. **居中金额光学居中**：类似居中大字 `¥128` 或 `$45`，把货币符号略微缩小或悬于数字左侧，使视觉中心落在数字本身而非偏右。
3. **标题与段落防孤字**：Web 端标题使用 `text-wrap: balance`，长正文使用 `text-wrap: pretty`，防止最后一行只剩 1–2 个孤零零的字。
4. **行宽控制（Measure）**：长文阅读区控制单行 **55–75 个英文字符**（或 **28–40 个汉字**，约 `60ch–68ch` / `640–720px`），超宽屏严禁让一行文字横跨 1600px。
5. **垂直光学居中**：图标与单行文字并排、按钮内文字居中时，检查基线与大写字母高度（Cap Height）视觉居中；现代浏览器可按需利用 `text-box-trim` / `text-box-edge` 或精细内边距校准，避免标签看起来往下沉。

---

## 4. 长文本、多语言与辅助缩放韧性

- **长文本截断与换行**：明确每处文字的溢出策略——单行标题 `truncate` + Tooltip 展示全称；列表摘要最多 `2–3` 行 `line-clamp`；长 URL/邮箱/单号加 `overflow-wrap: anywhere` 防止撑爆横向布局。
- **多语言膨胀预留**：若支持多语言（德语/法语/俄语往往比中文长 2–3 倍），按钮与标签容器禁止写死固定宽度（`width: 80px`），改用 `min-width` + 内边距弹性伸展。
- **尊重系统字体缩放**：
  - Web 使用 `rem` 定义字号与关键容器留白，确保浏览器放大到 **200%** 时不重叠、不裁切核心操作（WCAG 1.4.4）。
  - iOS 支持 Dynamic Type（从默认到 AX3 级别不截断主操作，必要时从横向排布自动转为纵向堆叠）。
  - Android 使用 `sp` 单位定义字号，配合弹性行高。
