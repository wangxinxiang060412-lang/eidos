# Frontend & Client Engineering Standards

所有设计最终必须落在**可真实运行、零假交互、数据闭环完整、架构克制**的生产代码上。禁止交付“视觉华丽但按钮点不动”的静态壳子。

---

## 1. 真实功能闭环核查 12 条

每个交付的页面与模块，代码层面必须逐一验证：

1. **所有交互控件真实接线**：每个可见按钮、链接、Tab、开关、筛选器、排序器、搜索框、分页、下拉菜单必须绑定真实状态或业务逻辑；禁止 `onClick={() => {}}`、`href="#"` 死链或纯假成功 Toast。
2. **完整 CRUD 与数据流**：若业务含新建/编辑/删除/搜索/筛选，必须从入口到数据源（真实 API、数据库或本地持久化 `localStorage` / `IndexedDB` / `SQLite` / `UserDefaults` / `DataStore`）端到端打通，刷新页面后状态按预期保留。
3. **缺依赖必须诚实声明**：若当前仓库尚无后端接口、支付沙箱或特定原生 SDK 权限导致某功能无法真实提交，**必须明确告知用户受阻项并清晰标注边界**，严禁用假装成功掩盖未实现。
4. **表单健壮性**：处理受控输入、校验时机、防重复提交、异步提交中禁用、提交失败保留表单输入、未保存离开确认。
5. **路由与深层链接**：URL 参数/路由参数与页面筛选/详情状态同步；处理非法 ID、404、权限不足重定向及返回栈恢复。
6. **状态管理克制**：区分本地 UI 态（弹层开关、Hover）、共享客户端态（当前用户、主题、筛选）与服务端缓存态（TanStack Query / SWR / ViewModel）；避免把所有局部开关全塞进全局 Store 导致整树重渲染。
7. **健壮的错误处理与边界**：配置 Error Boundary / 兜底异常捕获、网络重试/取消（`AbortController` 防止竞态覆写旧请求）、空值安全防御。
8. **手势与事件清理**：监听窗口 `resize`、键盘快捷键、`IntersectionObserver`、定时器、WebSocket 与动画帧 `requestAnimationFrame` 时，必须在组件卸载/生命周期销毁时 100% 释放，防止内存泄漏与鬼影回调。
9. **复用既有技术栈（严禁乱换框架）**：
   - 存量项目优先复用现有的框架、UI 库、样式方案、状态管理、图标包与打包器。
   - **禁止无故替换框架、引入重型第三方动画/组件库或扩大工程复杂度**；新增任何依赖前必须确认必要性与包体积代价。
10. **无障碍原语优先**：Web 端 Modal、Dropdown、Popover、Select、Tabs、Tooltip 等复杂焦点与 ARIA 管理组件，优先复用项目内成熟无障碍原语（如 Radix UI / React Aria / Base UI / Headless UI）或原生 `<dialog>` / Popover API，避免手写缺陷弹窗。
11. **类型安全与零噪音编译**：运行项目自身的 typecheck、lint 与 build 命令，修复自己引入的全部类型错误、Console 报错、React/SwiftUI/Compose 运行时 Warning（存量无关报错单独如实汇报）。
12. **样式隔离与 Token 驱动**：所有颜色、圆角、阴影、字号、间距从统一 Token / CSS Variables / Theme 派生，不污染全局选择器，不在业务组件硬编码魔法值。
