# Runtime Visual & Motion Verification Protocol

**铁律：永远不能仅靠“读了一遍自己写的代码”就宣称界面、排版或动效已经做好。**
本协议吸收 Stageshow（`benjitaylor/skills`, MIT）的帧级排演（Rehearsal）、“所见→所改”表与新鲜视角审查思想，并适配真实生产应用的全端验收。

---

## 1. 强制验收闭环

```text
分析 → 设计 → 实现 → 真实运行 → 截图/录屏取证 → 独立审查 → 修复 → 重新取证验收
```

任何一次视觉或布局修改完成后，**必须重新截图/运行确认**，绝不在改完最后一行代码后不看画面直接收尾。

---

## 2. 按平台选择真实运行与取证工具

| 目标平台 | 推荐运行与取证工具 | 最低必须取证视图 |
|---|---|---|
| **Web / PWA / 桌面 Electron·Tauri** | 浏览器 / Playwright / Chrome DevTools MCP / 真实窗口截图 | 桌面宽屏（如 `1440×900`）+ 手机窄屏（`390×844`）+ 深色模式（若支持）+ 关键交互态（弹层/错误/空态/焦点态） |
| **iOS / iPadOS** | Xcode + iOS Simulator（`xcrun simctl io booted screenshot / recordVideo`） | 标准 iPhone + 小屏/大字号（Dynamic Type）+ 横屏/iPad（若支持）+ 深色模式 |
| **Android** | Android Studio / Emulator / `adb exec-out screencap` / `android screen` | 常规手机 + Edge-to-Edge 状态栏/导航栏 + 系统暗色 + 字体放大 |
| **微信小程序** | 微信开发者工具模拟器 / 真机预览 | 顶部右上角胶囊避让截图 + 底部安全区截图 + iPhone/Android 双机型 |
| **游戏 UI / HUD** | Unity Editor / Unreal PIE / 实机录屏 | 16:9 标准屏 + 21:9 超宽/小屏 + 高压动态战斗背景上的 HUD 可读性 + 手柄焦点导航录屏 |

## 3. 动效帧级验收（静态图无法证明动效质量）

对于页面转场、卡片展开、Bottom Sheet、列表增删、拖拽与状态切换：
1. **不能只看起止静态图**：尽可能通过录屏、Playwright Video / 间隔抽帧（如关键节拍每 `50–80ms` 截一帧）或慢放（如 0.25× 速度）核查中间帧。
2. **重点核查 6 类隐形动效缺陷**：
   - **边缘切字**：容器高度展开/折叠时边框硬切正在显示的文字。
   - **落位跳变（Settle Snap / Handoff Shift）**：动画结束瞬间位置跳 1–2px、字重变粗或字形微抖。
   - **锚点漂移（Anchor Drift）**：筛选列表变短时，已打开的下拉框/Popover 上下乱移。
   - **空壳白帧**：面板先展开一个空框停顿 200ms 再闪出文字。
   - **打断崩溃**：动画放到一半立即反向点击或连续点击，界面卡死、重叠或跳回初始态。
   - **减少动效失效**：开启 `prefers-reduced-motion: reduce` 后仍有大幅位移/缩放或状态直接丢失。

## 4. “所见 → 所改”快速诊断表（看图修界面）

查看真实截图与录屏时，用“最挑剔的设计总监截一小块图问你‘这是什么？’”的眼光审视画面：

| 截图 / 录屏中看到的现象 | 立即执行的精准修复 |
|---|---|
| 卡片内部四周留白不均（顶部宽、底部按钮紧贴底边） | 统一卡片/弹窗四边内边距，检查底部操作区清距 |
| 标题与副标题离得太远，或比相邻两行还远 | 严格执行接近性不等式：标题-副标题 `4–6px`，项间距 `12–16px` |
| 边框/分割线离文字仅 1–3px（近切边） | 要么精确对齐 `0px`，要么拉开到 `≥ 8–12px` |
| 列表页只填了半屏、底下留一大片死白空洞，或强行把行距拉成巨高 | 恢复合理行高（`44–56px`），通过合理信息组织或紧凑容器高度承载，严禁虚拉行距 |
| 数据单位/金额折成两行（如 `128` 在上、`元/月` 掉到下一行） | 对数值与单位加 `whitespace-nowrap` 或缩小字号适配窄列 |
| 图标与文字垂直看起来没居中、或小图标混用实心与线框 | 统一单一图标家族与线宽，按大写字母高度微调垂直光学对齐 |
| 狭小手机宽下横向出现滚动条，或右侧按钮被挤扁成椭圆 | 图标/徽章加 `flex-shrink: 0`，检查长文本 `min-width: 0` 与换行/截断 |
| 浅灰辅助文字在白底或毛玻璃上发虚看不清 | 立即加深字色至 WCAG AA ≥ 4.5:1，或给背景加不透明衬底 |
| 点击按钮后无明显视觉变化、或提交时按钮变窄把旁边按钮拉歪 | 补齐 `:active` 即时按压态与 Loading 态锁定最小宽度 |
| 深色模式下大片黑坨阴影、或卡片和背景融在一起分不清边界 | 去掉黑阴影，改为更亮一档的表面灰阶 + `rgba(255,255,255,0.08)` 细边/顶光 |
| 连续点击或空数据/断网时出现白屏、无限转圈或原始错误堆栈 | 按 [interaction-states.md](./interaction-states.md) 补齐空态、重试与状态保护 |

## 5. 诚实披露规则（Environment Constraints）

如果当前运行环境**确实无法**启动模拟器、连接真机、运行游戏引擎或录制视频：
1. 必须尽最大可能完成**当前环境可及的验证**（如静态类型检查、单元测试、构建打包、无头浏览器截图、脚本校验）。
2. 在交付总结或 [delivery-report.md](../templates/delivery-report.md) 中明确列出 **`Not Checked（尚未在真实环境验证项）`** 及原因与用户复测步骤。
3. **绝对禁止**编造截图观察结果，或把未实际跑过的页面宣称为“视觉与动效已验收通过”。
