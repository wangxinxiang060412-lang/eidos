# Runtime Visual, Motion & Content Verification Protocol

**铁律：永远不能仅靠“读了一遍自己写的代码”就宣称界面、排版、文案或动效已经做好。**
本协议吸收 Stageshow（`benjitaylor/skills`, MIT）的帧级排演（Rehearsal）、“所见→所改”表与新鲜视角审查思想，并升级为生产级 **14 步运行验收 + 前后对比 + 负收益主动回退** 闭环。

---

## 1. 强制闭环与 14 步运行验收清单

```text
分析 → 方向/配色确认 → 设计 → 实现 → 14步运行取证 → Content Audit → 前后对比与精修 → 复测
```

每一次主要优化完成后，尽最大可能在真实环境中逐项执行以下 14 步：
1. **实际运行项目**（确认构建与启动零新增报错、Console 干净）
2. **获取全局与局部细节截图**（同时检视整页视觉重心/节奏与局部 2× 对齐/基线/圆角/图标细节）
3. **检查不同设备与视口尺寸**（桌面宽屏 `1440×900`、移动窄屏 `390×844`、极端 `320px` 及深色模式）
4. **实际点击全部主要操作入口**（验证无空壳按钮、点击即时反馈与热区准确）
5. **验证页面跳转、返回与保态**（检查返回后滚动位、筛选条件、深层链接兜底与系统返回一致性）
6. **检查所有弹窗/菜单/日期选择器/Sheet 的出现与收起**（核对 `transform-origin` 锚点、收起速度与焦点回归）
7. **检查动效连续性与打断**（通过录屏或 `50–80ms` 间隔抽帧核查：无切字、无落位跳变、无锚点漂移、连点不卡死、`prefers-reduced-motion` 正常）
8. **检查列表与页面滚动**（滚到最顶/最底无穿帮、吸顶层不遮挡、滚动流畅无掉帧）
9. **检查数据展示准确性**（核对数值对齐 `tabular-nums`、比例零基线、无单位折行与空/断点区分）
10. **检查页面边界、安全区域与导航栏衔接**（顶部状态栏/胶囊/灵动岛、底部手势区防遮挡、软键盘避让）
11. **检查异常状态闭环**（空态、骨架加载、校验失败、断网/报错重试、撤销恢复、未保存离开拦截）
12. **检查功能完整性与文案审计（Content Audit）**（数据持久化刷新保留、全范围文案无 AI 模板痕、与程序真实状态 100% 一致）
13. **再次执行独立审美与高影响力精修审查**（对照 [visual-refinement.md](./visual-refinement.md) 20 项雷达排查低成本高收益细节）
14. **修复发现的问题并重新运行取证验证**（绝不在最后一次代码改动后不看画面直接宣布完工）

## 2. 按平台选择取证工具

| 目标平台 | 推荐运行与取证工具 |
|---|---|
| **Web / SaaS / 数据大屏 / Electron·Tauri** | 浏览器 / Playwright（整页 + 局部截图 + Video 录制）/ Chrome DevTools Performance |
| **iOS / iPadOS** | Xcode + iOS Simulator（`xcrun simctl io booted screenshot / recordVideo`） |
| **Android** | Android Studio / Emulator / `adb exec-out screencap` / `android screen` |
| **微信小程序** | 微信开发者工具模拟器 / 真机预览（重点取证胶囊避让与底部安全区） |
| **游戏 UI / 智能终端** | Unity Editor / Unreal PIE / 目标分辨率与动态背景录屏 + 手柄/遥控器焦点导航录像 |

## 3. 前后对比与“负收益主动回退”铁律

- **修改前后视觉对比（Before vs After）**：在存量优化或精修任务中，尽可能先截取改动前基线图，再与改动后同视口、同状态截图并排比对。
- **客观衡量收益**：逐项判断改动是否真正提升了——① 功能清晰度、② 操作效率、③ 层次与对齐、④ 可读性、⑤ 边界与动效连续性。
- **零收益 / 负收益主动回退（Rollback Rule）**：如果某项“看似更设计感”的修改在实机对比中**没有带来明确收益，甚至导致信息更难扫视、操作更繁琐或整体不协调**，必须**果断撤销回退或重新设计**，严禁因为已经写了代码就硬推上线。

## 4. “所见 → 所改”快速诊断表

| 截图 / 录屏中观察到的现象 | 立即执行的精准修复 |
|---|---|
| 卡片/弹窗四周留白不均（上松下挤） | 统一四边光学内边距，补足底部操作区清距 |
| 标题下有一句空洞解释副标题或堆叠装饰小胶囊 | 删除废话副标题与多余胶囊，用字重与留白建层级 |
| 边框/分割线距文字仅 1–3px（近切边） | 精确对齐 `0px` 或拉开至 `≥ 8–12px` |
| 底部列表最后一项被底栏或悬浮按钮挡住 | 底部内容容器增加 `底栏高 + safe-area + 16px` 内边距 |
| 数据单位折行或表格数字小数点歪斜 | 启用 `tabular-nums`、数值右对齐、`whitespace-nowrap` |
| 点击按钮打开菜单/日期选择器却从屏幕中央闪出 | 修正 `transform-origin` 至按钮锚点，补 180ms 展开与 140ms 收起 |
| 展开/折叠时容器底边硬劈文字或落位跳动 1px | 改用 Grid Row `0fr→1fr` 配合内容错峰淡入淡出，核对偶数像素盒 |
| 狭小屏出现横向滚动条或图标被压成椭圆 | 图标加 `flex-shrink: 0`，文本列设 `min-width: 0` 与合理折行/截断 |
| 浅灰辅助文字或毛玻璃上文字发虚看不清 | 加深至 WCAG AA ≥ 4.5:1 或加不透明衬底/暗色保护层 |
| 深色模式黑坨阴影脏乱或卡片边界消失 | 去掉黑影，改用提亮一档的表面色阶 + 顶部 `rgba(255,255,255,0.06)` 微光 |

## 5. 诚实披露规则（Environment Constraints）

若当前运行环境确实无法启动真机/模拟器/录屏：完成当前环境可及的全部工程检查，在 [delivery-report.md](../templates/delivery-report.md) 的 **`Not Checked`** 区块逐项透明列出受限原因与复测指南，**严禁伪造已验证结论**。
