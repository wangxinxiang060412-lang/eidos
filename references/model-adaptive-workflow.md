# Design Decision Engine & Model-Adaptive Execution

EIDOS 必须做到：**既能拉高较小参数模型的稳定交付下限，又不束缚前沿大模型的高阶审美创造力上限。**
核心方法是将模糊审美目标拆解为**可执行的 10 槽规范与确定性决策树**，并按模型能力与任务开放度分级授权。

---

## 1. 禁用模糊指令 → 强制转化为可检查动作

执行设计、代码编写或审查时，禁止停留在左侧空洞描述，必须按右侧可验证标准落盘：

| 模糊无效指令（禁止作为最终标准） | 可执行的确定性拆解 |
|---|---|
| “让界面更高级” | 1) 减少至少 1 层嵌套容器；2) 严格落盘 60-30-10 色度与 3 级文字对比度；3) 校准同心圆角、留白不等式与柔和阴影/暗色表面阶梯；4) 统一单一图标家族与 `tabular-nums`。 |
| “让动效更丝滑” | 1) 为触发控件设定准确 `transform-origin`；2) 按 Spatial（`220–320ms`）与 Effects（`140–180ms`）分离时长曲线；3) 仅动画 `transform/opacity`；4) 实测中途打断、快速连点与 `prefers-reduced-motion`。 |
| “优化页面审美” | 按 [visual-refinement.md](./visual-refinement.md) 20 项精修雷达与 [anti-ai-ui.md](./anti-ai-ui.md) 26 项排雷表逐条产出问题定位、修改方案与前后截图对比。 |
| “提高设计感” | 完成 [aesthetic-reasoning.md](./aesthetic-reasoning.md) 8 维产品诊断，确定贴合领域的 11 支柱视觉方向与 1 处克制品牌工艺细节，绝非堆渐变和毛玻璃。 |
| “让界面符合用户习惯” | 逐页通过 [user-psychology.md](./user-psychology.md) 6 问即时理解测试与 7 问功能直觉检查，确保高频核心任务 1–3 步可达且遵循目标平台 HIG。 |

## 2. 10 槽结构化设计决策协议

每当制定重要设计修改或新建规范/组件时，按以下 10 槽校验逻辑完整性（无需机械输出全部 10 段废话，但思考和评审必须全部覆盖）：

1. **检查对象**：具体页面、区域、组件或交互流
2. **问题识别条件**：客观可观察的触发条件（如对比度 <4.5:1、边距不均、点击无反馈）
3. **判断依据**：锚定具体原则（10 级优先级阶梯、WCAG 2.2、Jakob/Fitts/Hick、平台 HIG）
4. **设计决策逻辑**：为什么选方案 A 而不是 B（结合产品定位与场景）
5. **推荐处理方法**：精确到 Token、数值、结构或组件类型的可执行方案
6. **不适用的情况**：明确边界，防止教条式误用
7. **反面案例**：参照 [bad-patterns.md](../examples/bad-patterns.md) 避免的坑
8. **正面案例**：参照 [good-patterns.md](../examples/good-patterns.md) 的工艺基准
9. **实施要求**：代码层面的状态、无障碍、性能与不破坏存量边界
10. **验收方式**：明确的运行操作、目标视口与前后截图/录屏判据

## 3. 五大核心确定性决策树（低参数模型防跑偏护栏）

### 决策树 A：配色能不能改？
```text
现有项目有配色吗？
 ├─ 否（0→1 全新项目）
 │   ├─ 用户指定了品牌色/风格 → 锁定用户主色，推导合规中性阶梯与语义状态色
 │   └─ 用户授权 AI 决定 → 从 8 维分析推导独立色板，验证全阶对比度 ≥4.5:1
 └─ 是（已有配色/设计稿/半成品）
     ├─ 11 维色彩审查基本合理 → 【保留现有配色】，仅做对比度与表面微调
     └─ 存在明显缺陷 → 输出 2–3 套完整方案 + 同屏预览 → 【等待用户确认后方可修改】
```

### 决策树 B：内容要不要放进卡片？
```text
该信息块是独立可操作的异构实体（如商品/项目/媒体预览）吗？
 ├─ 否 → 是同构高频扫描记录？→ 用【列表行 / 分组列表】
 │     → 是多维精确对比数值？→ 用【数据表格】
 │     → 是正文阅读或表单？  → 用【开放画布 + 留白分组】
 └─ 是 → 卡片外面已经有带边框的父卡片了吗？
         ├─ 是 → 去掉外层或内层边框（严禁卡片套卡片）
         └─ 否 → 使用单层克制卡片 + 同心圆角
```

### 决策树 C：数据该怎么展示？
```text
用户核心诉求是？
 ├─ 看 1 个核心数字 + 变化 → 【Hero Stat + 周期对比 + 可选 Sparkline】
 ├─ 扫 3–5 个关联指标     → 【紧凑 Metric Strip】（禁堆重复厚卡片）
 ├─ 查明细/核对精确数值   → 【表格（桌面）/ 结构化列表（移动）】
 ├─ 看时间趋势            → 【折线图 / 轻填充面积图】
 ├─ 比较分类排名          → 【水平条形图 / 零基线柱状图】
 └─ 看比例/目标进度       → 【≤4项精简条形或直条进度】（禁花哨 3D 饼图）
```

### 决策树 D：导航与页面边界怎么衔接？
```text
页面核心内容是？
 ├─ 强沉浸媒体/地图/封面 → 【全出血背景延伸 + 滚动渐显保护层 / 平台材质】
 ├─ B 端工作台/表格/专业工具 → 【清晰 1px 硬边界 + 吸顶表头/工具栏】
 └─ 常规消费/阅读/设置 → 【静止无缝自然流 → 滚动后平滑浮现 1px 细线或轻影】
 + 所有页面强制：底部内容预留 `底栏高 + safe-area + 16px` 防遮挡
```

### 决策树 E：交互动效怎么定？
```text
交互类型是？
 ├─ 按钮按压 / 选中态 / Hover → Effects（0–160ms，零回弹）
 ├─ 菜单 / 日期选择 / Popover → 锚点 `transform-origin` 展开（180–220ms 入 / 140ms 出）
 ├─ Bottom Sheet / 抽屉 / 折叠 → 边缘滑入或 Grid 空间展开（240–320ms 入 / 180ms 出，不切字）
 ├─ 同页切换 / 详情展开       → 保留稳定外框，仅过渡变化区或条件合适的共享元素（≤340ms）
 └─ 任意动效强制要求：可中途打断 + 连点安全 + prefers-reduced-motion 降级
```

## 4. 模型能力自适应模式（保下限，不限上限）

| 维度 | 标准护栏模式（适合中小参数模型 / 快速高确定性交付） | 自主精研模式（适合高推理前沿模型 / 品牌旗舰与创新设计） |
|---|---|---|
| **审美方向** | 直接从 [visual-design.md](./visual-design.md) 6 大原型选型并套用已通过 WCAG 校验的色阶与 [design-tokens.json](../templates/design-tokens.json) | 基于 [aesthetic-reasoning.md](./aesthetic-reasoning.md) 11 支柱从零定制独一无二的跨学科美术语言与品牌细节，仍严格通过 WCAG 校验 |
| **组件与布局** | 严格遵循 5 大决策树与 [good-patterns.md](../examples/good-patterns.md) 经过验证的代码配方 | 允许打破常规网格与组件组合以服务独特产品叙事，前提是不违背 10 级优先级阶梯与用户习惯 |
| **动效实现** | 严格采用 [motion-design.md](./motion-design.md) 标准 Production Tokens | 可编排定制手势驱动物理与多阶段微交互编排，仍严守响应速度与可打断性 |
| **不可妥协的共同底线** | **两种模式均强制遵守**：10 级优先级阶梯、配色确认门禁、零假按钮、Anti-AI 排雷、14 步真实运行验收与负收益回退 | 同左（自由度永远服务于产品本质，绝不凌驾于可用性与功能完整性） |
