# Interaction Design: Controls, Touch Zones, Containers & Feedback

每一个可交互元素都必须回答三个问题：**它能被一眼认出来吗？它好点且防误触吗？点下去之后有真实且及时的闭环吗？**

---

## 1. 按钮与点击热区审查 10 项规范

审查项目中所有按钮、图标按钮、可点击卡片、列表行、菜单、工具栏与手势热区：

1. **最小点击热区硬标准**：
   - **iOS / 微信小程序**：视觉尺寸可紧凑，但实际点击热区 **≥ 44×44 pt**。
   - **Android (M3)**：实际触控目标 **≥ 48×48 dp**。
   - **Web / Desktop**：遵循 WCAG 2.2 SC 2.5.8 最低 **≥ 24×24 CSS px**（移动端 Web 仍按 **44×44 px** 触控标准；桌面常规按钮高度建议 **32–40px**）。
   - 若视觉图标仅 16–20px，必须用透明 `padding` 或伪元素/HitSlop 扩展热区，且相邻热区之间保持 **≥ 8px** 间距防误触。
2. **唯一主次层级（按钮语法）**：
   - **Primary（实心高对比）**：每屏/每个弹窗区域**最多 1 个**，代表最核心正向动作。
   - **Secondary（浅底或克制描边）**：并列辅助动作，不与 Primary 争抢视觉重心。
   - **Tertiary / Ghost（无底纯文字或图标）**：高频低干扰操作（如取消、编辑、工具栏操作）。
   - **Destructive（语义红/警示态）**：仅用于删除、停用、清空等不可逆或高损动作；在确认弹窗内可作为实心红按钮，在常规列表/表单中默认用文字或次级描边形式，**绝不与主保存按钮紧贴且同权重**。
3. **移动端拇指区与单手策略**：
   - 拇指自然弧区（屏幕中下部）优先放置核心主操作、导航切换与高频输入；顶部保留只读标题、搜索触发或低频管理操作。
   - 兼顾左手与右手习惯：关键单按钮可居中或通栏；不要把全部核心操作死板贴死在极底右角。
   - **反机械底部堆积**：绝不把所有按钮无脑全塞进屏幕底部变成拥挤的“遥控器”。
4. **图标可读性**：核心操作或含义不自明的图标必须配简短文字标签（或桌面端提供 300ms 延迟 Tooltip + 无障碍 `aria-label`）；严禁让用户猜抽象符号。
5. **消除冗余与空壳按钮**：删除重复触发同一功能的按钮；**严禁任何无事件绑定、`onClick={() => {}}` 或仅 `console.log` 的假按钮**。

## 2. 按钮状态机（按需启用，拒绝机械堆砌）

根据控件真实职责配置必要状态，每个状态必须视觉可辨且符合无障碍对比度：

| 状态 | 视觉与行为规范 | 适用范围 |
|---|---|---|
| **Default** | 清晰可点示能，符合主次层级 | 全部 |
| **Hover** | 桌面/指针端微调底色明度（+4%–8% 或填充同色系下一档，**实心主按钮悬停保持本色系深化，严禁灰掉**），`120–150ms` 过渡 | Web / Desktop / iPad 指针 |
| **Active / Pressed** | 即时反馈（0ms 响应）：轻微按压缩放 `scale(0.97–0.98)` 或透明度/底色加深；绝不拖延 | 全部 |
| **Focus-Visible** | 清晰键盘/手柄焦点环（≥2px，与背景对比度 ≥3:1，偏移 2px），**仅键盘/导航聚焦时显现**（`:focus-visible`），避免鼠标点击残留难看黑框 | 全部（Web / 桌面 / 游戏必做） |
| **Selected / Open** | 选中或关联弹层打开时保持明确高亮/按住态（如 `data-open`），与未选中态差异明确 | Toggle / Tab / Popover Trigger |
| **Disabled** | 降低对比度并禁用指针/点击，但仍保持可读；若用户可能困惑为何不可点，旁边给出原因提示而非静默灰掉 | 表单校验/权限不足 |
| **Loading** | 点击提交后锁定防重复提交，原地保留按钮宽度（**严禁按钮宽度塌缩导致周围元素跳动**），内嵌旋转指示器或进度文案 | 异步网络/耗时提交 |
| **Success / Error** | 仅在原地短反馈有价值时使用（如“已复制 ✓”持续 1.5s 复原）；常规提交后直接进入目标结果态或展示 Toast | 复制 / 快速保存 / 内联提交 |

## 3. 容器选型矩阵：什么时候不该用卡片？

**核心原则：优先通过留白、对齐、字重层级与分组标题组织信息，不要把一切内容都关进带边框和阴影的卡片里。**

在用卡片前，先执行 **“卡片三问”**：
1. 每一项是否是**独立完整的信息实体**（如商品、项目、订单、课程）？
2. 它是否需要清晰的**独立点击边界**或与其他异构模块区分？
3. 去掉外边框和阴影后，元素归属是否真的会混淆？

若答案多为“否”，按此表选择更合适的容器：

| 内容特征 | 最佳容器 | 说明 |
|---|---|---|
| 同构高频扫描数据（消息、设置、订单明细、文件列表） | **列表（List） / 分组列表（Inset Grouped List）** | 用统一行高（44–56px）+ 精细内嵌分割线或交替间距，扫描效率远高于卡片网格 |
| 多维对比、可排序/筛选/对齐数值 | **数据表格（Table）** | 列宽对齐、数值右对齐 + `tabular-nums`，移动端转为结构化摘要行 |
| 正文阅读、详情说明、表单填写 | **开放画布内容区（Open Canvas Section）** | 直接铺在页面主画布上，用标题与 24–32px 区块留白分隔，不额外套盒 |
| 富媒体预览、异构信息聚合、可拖拽看板项 | **卡片（Card）** | **最多 1 层嵌套**（严禁卡片套卡片）；内部统一留白（16–20px）；整卡可点时内部次级按钮必须做好事件隔离（`stopPropagation`）且视觉区隔 |
| 线性事件流、物流、操作记录 | **时间轴（Timeline）** | 垂直视觉连线 + 清晰时间节点，无需每条套独立厚卡片 |
| 指标监控、多图表分析 | **数据面板（Dashboard Grid）** | 主次分明（1 个核心趋势大区 + 精简关键 KPI），禁止铺满 12 张同等大小无主次指标卡 |

**卡片 6 项体检**：独立语义？无双重描边（边框+重阴影叠加）？无多余内部分割线？无嵌套卡片？点击区与内部按钮不冲突？内容变长/换行时不撑破邻居？

## 4. 微交互、触觉与音效规范

反馈强度必须与操作重要度成正比，严禁全量操作乱加震动和音效：

| 操作类型 | 视觉反馈 | 触觉反馈（移动端/手柄） | 音效（仅适合的应用/游戏） |
|---|---|---|---|
| 普通按钮点击 / Tab 切换 | 即时按压态 + 平滑指示器过渡 | 轻量 Selection / Light Impact（可选，克制） | 静音（效率软件不发声；游戏用极轻短促 UI 声） |
| 开关 Toggle / 滚轮刻度 / 吸附点 | 滑块跟手弹簧过渡 | Selection Feedback（微弱咔哒感） | 仅游戏/拟物硬件工具 |
| 长按触发菜单 / 拖拽拾起 | 轻微浮起（`scale 1.02–1.03` + 阴影加深） | Medium Impact（拾起瞬间单次） | 静音或轻触音 |
| 关键成功（支付/完成打卡/任务达成） | 清晰收尾确认（如勾号绘制/状态过渡） | Success Notification Haptic | 可选轻柔正面提示音 |
| 表单校验失败 / 不可操作边界 | 目标输入框轻度水平抖动（±4px，250ms）+ 明确错误文案 | Error / Warning Haptic | 游戏/特定终端警示短音 |
| 删除 / 归档 | 行平滑折叠闭合 + 底部弹出“已删除 · 撤销”Toast | Rigid / Heavy Impact（仅重要破坏操作） | 静音或低沉确认音 |
